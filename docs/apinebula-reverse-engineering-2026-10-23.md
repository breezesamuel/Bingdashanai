## 一、它到底是什么

**一句话**：面向中国开发者的 **AI 模型 API 聚合/中转平台**（"一个接口，接入全球顶尖 AI 模型"）。
不是 agent 产品，不是 SaaS 工作台——是**卖 token 的中间商**，用"支付宝充值 + OpenAI 兼容 + 稳定直连"三件事赚差价。

| 维度 | 实测事实 |
|------|---------|
| 定位 | Anthropic + OpenAI 模型统一接入（Gemini/图像模型也在列表） |
| 计费 | **预付费余额制**，¥1 余额 = $1 模型价格额度；最低充值 ¥20；余额永久有效 |
| 支付 | 支付宝（明确"无需境外信用卡"），可开增值税发票 |
| 价格 | 按模型分列：输入/输出/缓存读取（每 1M tokens）+ 折扣（0.58 折 ~ 1.5 折）+ 在线状态 |
| 规模自述 | 55 个实际模型、5,000+ 开发者、99.9% 可用性、延迟 <200ms |
| 技术卖点 | 多节点冗余、自动故障转移、无需代理、OpenAI SDK 只改 base_url |
| 控制台能力 | 统一 API Key、**子 key（限速/配额/过期）**、按模型/项目/时间用量监控、账单导出、请求日志（延迟+错误）、团队管理 |
| 商业扩展 | 企业采购、合作计划（partner）、文档站 docs.apinebula.ai |
| 信任装置 | 6 条实名证言（CTO/独立开发者/产品经理/研究生/技术总监/全栈）、FAQ 6 条、SLA 数字 |

## 二、它的页面结构（信息架构）

```
落地页 /zh
├─ 顶部导航：模型 · 定价 · 功能 · FAQ · 文档 · 控制台 · 企业采购 · 合作计划 · 登录 · 开始使用
├─ Hero：一句价值主张 + 双 CTA（免费注册 / 查看定价）+ 4 个硬指标（55 模型 / 5000+ 开发者 / 99.9% / ¥20 起充）
├─ 价格跑马灯：5 个模型 × 输入/输出价（制造"便宜"的即时感）
├─ 核心功能 6 宫格：01 统一 Key · 02 稳定直连 · 03 支付宝充值 · 04 用量监控 · 05 请求日志 · 06 OpenAI 兼容
├─ 透明定价表：模型 / 输入 / 输出 / 缓存 / 折扣 / 状态
├─ 用户评价：6 条按角色分布（覆盖 6 类买家）
├─ FAQ：6 条，全部在打消"能不能替代官方 / 怎么换算 / 稳不稳 / 能不能企业采购"
└─ 底部：用户协议 · 隐私政策 · 关于 · 文档
```

**转化设计要点（可抄的）**
1. **数字先行**：Hero 不放功能截图，放 4 个可验证数字。
2. **价格即内容**：价格表直接放在落地页，不藏到二级页——降低"怕被宰"的焦虑。
3. **角色化证言**：6 条证言刚好对应 6 类目标客户，读者总能对号入座。
4. **FAQ 只回答购买阻力**：不写产品说明，只写"凭什么信你"。
5. **双入口**：开发者走控制台，企业走 enterprise，合作方走 partner——同一流量三种变现。

## 三、和我们（丙大山 AI Agent）的关系：不是竞品，是**上游供应商 + 设计参照**

- **供应商价值**：我们当前卡在「LLM 供应商凭据」（火山 ep-、Agnes base URL、NVIDIA NIM 轮换）。APINebula 这类聚合平台能**一个 key 打通多模型**，且支持支付宝——如果对方稳定，可作为 `core/providers.js` 的一个新 provider（OpenAI 兼容，改 base_url 即可）。**未接入，仅作备选记录**：接入前需验证合规、留存与数据出境条款。
- **设计参照**：我们缺的正是它做得最重的三件事——**用量可见、成本可见、信任可见**。

## 四、已落地到本项目的 3 项（不是抄文案，是补能力）

| APINebula 的做法 | 我们的缺口 | 本次落地 |
|---|---|---|
| 实时用量监控（按模型/项目/时间） | `core/cost.js` 有台账，但**没有任何接口暴露** → 毛利黑箱 | 新增 `GET /v1/usage/margin`：同期营收 + LLM 成本估算 + 毛利率 + 成本覆盖率 + 分供应商明细 + 今日分区用量；**必须管理令牌**；明确标注"估算、非财务凭证" |
| 透明价格表（输入/输出/缓存 + 折扣 + 状态） | 订阅墙只显示套餐价，不显示"每个功能区每天能用多少" | 已有（`/v1/subs/quota` + 额度表），本次补齐**三语标签/说明**，英文/阿文客户不再看到中文 |
| 价格/能力分级（折扣 + 档位） | 成熟度是人工填的，会失真 | 新增 `core/maturity.js` + `GET /v1/maturity/report`：按真实用量与故障出升降级建议，已把 skill/org/evolve 升为 `tested` |

**未落地（有意为之）**：子 key/限速/团队管理属于"卖 API"的能力，与我们的订阅制产品不同源；等真的做 API 转售再建，避免过度建设。

## 五、可继续借鉴的 4 个点（按 ROI 排序）

1. **请求日志 + 延迟/错误可视化**（我们只有 audit 文本）→ 做 `/v1/apilog`，排障与 SLA 承诺的前提。
2. **账单导出（CSV）** → 已有 `store.toCsv`，接一个下载路由即可，B 端客户会问。
3. **"¥1=$1" 式的一句话换算** → 我们的等价物是"¥99/月 = 每天 ¥3.3，约一次外卖"；落地页缺这句。
4. **企业采购页** → 我们有 B2B 履约流程（`fulfillment`），但没有对外报价页；这是最直接的增收缺口。
