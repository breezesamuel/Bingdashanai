# 陪护全链路审计（管理中心 · 子女端 · 老人端 · 监控中心 · 陪护机器人）

日期：2026-10-23　范围：`core/care.js`、`/v1/care/*`、`web/care/*`、`core/assist.js`、`core/saas-loop.js`
原则：**没有证据的闭环不算闭环**；分母为 0 就显示 `null`，未定价就说"未定价"。

---

## 0. 一句话结论

| 问题 | 结论 |
|---|---|
| 五端之间形成审计闭环了吗？ | **形成责任链闭环**：建档→绑定→设备→告警→SLA 升级→接单→闭环→任务→资料→审计，每一步都有状态、时限与留痕。 |
| 端到端形成商业闭环了吗？ | **没有**。`carePlan` 未定价、0 个家庭、0 收入。这是刻意的：定价属商业决策，不擅自上线。 |
| 他们如何协调/互动？ | 老人建档发邀请码 → 子女加入 → 设备心跳 → 出事告警按 SLA 升级 → 子女/监控中心接单闭环 → 任务与资料沉淀 → 巡检发现断点。 |
| 资料怎么提交/管理？ | 图片上传（≤1MB、magic bytes 校验）→ 落盘 `data/care-docs` → 元数据入库 → 仅家庭成员可下载 → **每次下载写审计**。 |
| 远程协助控制做了吗？ | 只做「协调 + 留痕」（请求/同意书/队列/接单/完成/撤回/过期）。**不做屏幕共享、键鼠接管**；四要件（可撤回授权+录制+遮蔽+断连）不齐不碰。 |
| 还有哪些没闭环？ | 短信/推送告警、健康数据加密、资料保留与删除、家属细粒度授权、多老人 UI、机器人硬件协议、定价与支付。见 §8。 |

## 1. 五端角色与权限矩阵

| 端 | 谁用 | 能做什么 | 明确不能做 | 鉴权 |
|---|---|---|---|---|
| 老人端 `/care/elder.html` | 老人本人 | 建档（必须本人勾同意）、一键 SOS、看/完成任务、拍照上传病历、看家人与设备状态、申请人工协助 | 不能给自己安排任务（避免"自证完成"）；不能看其他家庭 | `bd_care` 独立 Cookie（按浏览器，不按 IP） |
| 子女端 `/care/family.html` | 子女/家属 | 凭 6 位邀请码加入（需同意）、看告警、接单/闭环（必须写处理结果）、补健康档案、注册设备、安排任务、上传资料 | 不能替老人建档；不能改别人家庭；手机号只显示脱敏 | 同上 |
| 监控中心 `/care/center.html` | 运营/值守 | 全量家庭台账、设备在线率、告警队列、SLA 超时、接单/闭环、闭环体检 | 无管理令牌一律 403；不提供屏幕控制 | `x-admin-token` |
| 管理中心 `/ops.html` | 运营 | 协助队列、订阅闭环体检、审计结论、陪护入口 | 不直接改钱账 | `x-admin-token` |
| 陪护机器人 | 设备 | 心跳（电量/固件）、上报 SOS/跌倒/离线 | 不能读全家资料、不能代替人接单 | 设备令牌，服务端只存 `sha256`，**只回显一次** |

**越权测试（已固化）**：非成员读档案/告警/资料全部失败；陌生人不能接单；非成员下载资料被拒。

## 2. 端到端怎么协调（六条流程）

### A. 建档 → 绑定（责任链的起点）
1. 老人 `POST /v1/care/family/create`，`consent=true` 才允许；生成家庭 + 6 位邀请码 + 老人成员 + 空档案。
2. 子女 `POST /v1/care/family/join`（邀请码 + 同意）→ 成为 `guardian` → 家庭写 `boundAt`。
3. 幂等：重复建档返回同一家庭；重复加入返回 `already=true`。
4. **失败即拒绝**：无同意、错码、空称呼都不落库。

> 为什么坚持"老人本人同意"：这是健康资料处理的合法性基础（PIPL 敏感个人信息），也是产品伦理底线。

### B. 设备上线 / 掉线
1. 子女注册设备（app/robot/monitor/wearable）→ 返回一次性令牌。
2. 设备每 60s 心跳：`online`（<2min）/ `weak`（<10min）/ `offline`（>10min）。
3. 掉线自动建 **P1 告警**（同一设备当天只建一次，防刷屏）。
4. 设备恢复心跳 → 该设备未闭环的 `device_offline` 告警**自动闭环**（`resolvedBy=system`）。

### C. 出事 → 接单 → 闭环（最关键的 5 分钟）
1. 老人按 SOS（或机器人上报跌倒）→ `P0`，SLA 5 分钟，返回应通知的子女（手机号脱敏）+ "无回应拨 120"。
2. 5 分钟内同类型告警去重（老人连点不会刷屏）。
3. 子女/监控中心接单 → 记录 `ackMin`、`ackWithinSla`。
4. 闭环**必须写处理结果**（≥2 字），记录 `handleMin`。
5. 超时未接单 → 巡检写入 `escalatedAt` / `escalatedTo`（子女名单或监控中心）。

### D. 任务（服药/打卡/探访/测量）
1. 只有子女能安排（老人不能给自己安排，避免"自己证明自己做了"）。
2. 老人或子女完成后记录 `lateMin`；`daily/weekly` 自动生成下一次。
3. 超时 5 分钟自动 `missed`；近 7 天漏做进入闭环体检。

### E. 资料（病历/处方/出院小结/保险）
1. 上传图片（PNG/JPEG/WEBP/GIF，≤1MB，按文件头校验，不信任扩展名）。
2. 落盘 `data/care-docs`，文件名随机化；数据库只存元数据。
3. 列表不暴露磁盘文件名；下载必须通过成员归属校验。
4. **每次下载写审计**（doc id + 谁 + 时间）。

### F. 巡检（60 秒一次，模块内 20 秒节流）
- 设备离线 → P1；告警超时 → 升级；任务超时 → 漏做。
- 巡检幂等：同一设备当天不重复建离线告警；升级只写一次。

## 3. 与远程协助的边界（合规红线）

`core/assist.js` 解决的是"人帮人"的协调与证据，不是"接管老人的手机/电脑"：

| 做 | 不做 |
|---|---|
| 客户发起请求、勾同意书、排队、运营接单、完成归档、撤回、过期 | 屏幕共享、键鼠接管、静默录屏、读取客户相册/通讯录 |
| 全流程审计（谁、何时、对谁、做了什么） | 无同意书的"远程看看" |
| 拒绝后不得再次骚扰 | 把协助请求当销售线索倒卖 |

陪护场景里，老人端只放"申请人工协助"入口；协助员**默认看不到健康档案**。要看资料必须家属另行授权——这条"细粒度授权"尚未实现，列入 P1。

## 4. 审计闭环：断点检查清单

`GET /v1/care/loop`（管理令牌）每次返回 8 个阶段 + 9 类断点 + `nextAction`：

| 断点 | 严重度 | 现状 | 自动动作 |
|---|---|---|---|
| `family_no_guardian` 家庭没有绑定子女 | high | 可检测 | 提示把邀请码发给子女（没人绑定=告警没人接） |
| `member_no_consent` 缺同意书 | high | 可检测 | 补签；没有同意不得记录健康资料 |
| `profile_incomplete` 年龄/紧急联系人缺失 | medium | 可检测 | 一次补齐 |
| `device_offline` 设备离线 >10 分钟 | high | 可检测 | 先查没电/断网，2 小时未恢复上门 |
| `p0_unacked` P0 超时未接单 | high | 可检测 | 电话老人；无回应联系家属与 120 |
| `alert_open_24h` 告警 24h 未闭环 | high | 可检测 | 当天必须闭环或说明原因 |
| `task_missed_7d` 近 7 天漏做 | medium | 可检测 | 先确认是否已服药，避免重复用药 |
| `no_payer` 未指定付费人 | low | 可检测 | 默认第一位子女 |
| `billing_not_configured` 未定价 | high | **当前命中** | 定价后写 `settings.carePlan` 才能收费 |

`healthy` 只有在所有断点为 0 时才为 `true`；`nextAction` 永远指向最严重的非零断点。

## 5. 商业闭环：谁付钱、怎么收、利润从哪来

### 5.1 现状（诚实口径）
- 家庭 0、老人 0、子女 0、设备 0、告警 0、资料 0（生产库实测）。
- `carePlan.configured=false` → 闭环报告明确写"陪护收费未定价（无法形成商业闭环）"。
- 因此**当前陪护线收入 = 0**，不计入任何营收口径。

### 5.2 付费者不是老人，是子女
- **被服务者**：老人（65-85，独居/空巢/慢病）。
- **付费决策者**：子女（35-55，异地或双职工），焦虑驱动，怕"出事没人知道"。
- **第二客群**：社区养老站/护理机构（白标 + 监控中心 + 多床位）。

### 5.3 定价建议（**待拍板，未上线**）
| 档位 | 建议价 | 含什么 | 作用 |
|---|---|---|---|
| 种子试点 | ¥0（限 20 户） | 全套功能，换访谈/案例/转介绍 | 拿真实使用数据，不做长期免费 |
| 基础 | ¥99/月/老人 | 1 老人 + 3 家属 + SOS/告警/任务/资料 | 主力款，锚点"每天 ¥3.3" |
| 陪护 | ¥299/月/老人 | 设备接入 + 5 分钟 SLA + 每周报告 + 优先人工 | 提客单 |
| 机构 | ¥699/月/5 床位（或 ¥99/床/月） | 白标 + 监控中心 + 批量台账 | 走量 |

对比锚点：请护工 ¥200–300/天；养老院 ¥4000–8000/月；一次跌倒住院动辄数万元。

### 5.4 成本与毛利（估算，需账单校准）
- 最大成本是**监控中心值守人力**，不是服务器。
- 假设 1 名值守覆盖 150 户（P1 30 分钟 SLA）：150×99 = ¥14,850/月；值守 ¥6,000–8,000 + 短信/服务器 ¥1,000 → 毛利约 40–55%。
- 毛利对**告警量**敏感：每户每月 >8 次误报会吃掉利润 → 必须做告警分级与去重（已做 5 分钟去重、设备离线当天去重）。
- 硬件（机器人）走租赁/押金，不靠硬件赚差价。

### 5.5 利润杠杆（按优先级）
1. **SLA 分层**：基础 30 分钟 / 优先 5 分钟，价差 ¥100–150。
2. **年付**：85 折，先把现金流拿回来（续费率比单价更重要）。
3. **多老人家庭套餐**：第二位老人 +¥59/月（边际成本极低）。
4. **机构白标**：一家 50 床 = 50 个家庭，获客成本摊薄。
5. **增值服务**：陪诊、报告解读转介、适老化改造（抽佣，不自己做交付）。

## 6. 客户画像、粘性、频率、复购

### 6.1 老人群体细分（按付费意愿×风险）
| 细分 | 年龄 | 特征 | 需求 | 是否主攻 |
|---|---|---|---|---|
| 独居/空巢慢病 | 65–80 | 子女异地、怕麻烦、怕被监控 | SOS、吃药提醒、"有人知道" | **主攻** |
| 白天无人 | 70–85 | 与子女同城但白天独自 | 打卡、跌倒、异常提醒 | 主攻 |
| 术后/失能初期 | 60–75 | 需要护理记录、复诊提醒 | 资料、任务、家属协同 | 高付费但医疗风险高，慎接 |
| 活力老人 | 60–70 | 社交/学习需求 | 免费工具、转介绍 | 只做引流 |
| 重度失能 | any | 需 24h 医疗护理 | — | **不接**（超出能力边界） |

**喜好画像**：大字体（≥20px）、一屏一个动作、少输入、方言/语音优先、不要"被监视"的措辞（用"家人知道你平安"而不是"定位监控"）。

### 6.2 付费子女画像
- 35–55 岁，异地工作/双职工，年收入 15–50 万；父母 65+。
- 触发点：一次跌倒、一次住院、邻居出事、父母独居。
- 决策 1–3 天，先问"出事谁通知我""多久到""数据谁能看到"。
- 最怕：误报骚扰、隐私泄露、交了钱没人管。

### 6.3 粘性与频率
| 角色 | 健康频率 | 粘性来源 | 流失信号 |
|---|---|---|---|
| 老人 | 每日 2–4 次（打卡/用药/看任务） | 习惯 + 子女电话 | 连续 3 天不打卡 |
| 子女 | 每日 1 次查看 + 告警即时 | 安心感 + 每周报告 | 7 天不打开、告警不接单 |

北极星指标建议：**每周"有闭环的活跃家庭"**（至少 1 次任务完成或 1 次告警接单），而不是 DAU。

### 6.4 复购/续费
- 目标：3 个月续费 ≥60%，6 个月 ≥75%，年付转化 ≥30%。
- 增购：第二位老人 +¥59/月、机器人租赁、SLA 升级。
- 转介绍：子女社群/同事；NPS ≥40；"推荐一位送一个月"比打折有效。
- 预警：连续 2 周无任务完成 + 无查看 → 人工回访（在流失前）。

## 10. 本轮修复的其他问题（非陪护）

1. **同 WiFi 身份串号（严重）**：匿名身份按 IP×小时，老人和子女在同一 WiFi 下会被当成同一人 → 子女永远绑不上。已改为陪护专用 `bd_care` 浏览器 Cookie（随机 key），并加静态守卫防回归。
2. **成本口径**：支持 `provider:model` 精确单价；`glm-4-flash` 按官方免费记 ¥0；Agnes 价格未知标记 `unknown` → `cny=null`，不再假装“0 成本/100% 毛利”。
3. **供应商配置**：修正 Agnes base 为 `https://apihub.agnes-ai.com/v1`；智谱默认模型改为免费 `glm-4-flash`；NVIDIA 换成未下架的模型 ID；火山暴露 `endpointConfigured`（缺 `ep-` 即 false）；**`settings.provider` 已切到 `zhipu`**（Agnes 当前 429）。
4. **`.env` 权限**：从 644 收紧到 600（内含支付私钥/邮箱密码）。
5. **运维脚枪**：`pkill -f "node server.js"` 会连 SSH 会话自己一起杀（命令行里含同样字符串），导致 502。改为 `restart.sh` 按端口 PID 停止，已写入服务器。
6. **短信/邮件/订阅/资料删除/临时授权** 五个子系统一次性落地，全部 fail-closed，**任何未配置/未通过校验的路径都写审计、不虚报成功**。
